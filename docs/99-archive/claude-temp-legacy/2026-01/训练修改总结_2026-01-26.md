## 🔴 需要修改的问题

### 问题1: action_smoothness 符号错误

**文件**: `dashgo_env_v2.py` 第1010行

**当前代码**:
```python
action_smoothness = RewardTermCfg(
    func=reward_action_smoothness,
    weight=-0.01,  # ❌ 负权重
)
```

**问题**:
- 函数返回: `-sum(diff²)` （负数）
- 权重也是: `-0.01` （负数）
- 结果: 负 × 负 = 正奖励（刷分）

**日志证据**:
- action_smoothness 平均值: 307
- 100%的episode都是正数
- 反推动作差异: 5.56（严重抖动）

**影响评估**:
- ❌ 理论上: 奖励黑客漏洞
- ✅ 实际上: 被alive惩罚抵消（-832），净效果仍是惩罚
- ⚠️ 风险: 如果未来调整权重，错误会放大

**修改方案**:
```python
action_smoothness = RewardTermCfg(
    func=reward_action_smoothness,
    weight=0.01,  # ✅ 改为正数
)
```

**优先级**: 🟡 建议修复

### 问题4: LiDAR射线数优化（新增）

**文件**: `dashgo_env_v2.py` 第923行

**当前代码**:
```python
pattern_cfg=patterns.LidarPatternCfg(
    channels=1000,  # ❌ 1000点/圈
    horizontal_res=0.36,
    ...
)
```

**架构师建议**:
```python
pattern_cfg=patterns.LidarPatternCfg(
    channels=360,   # ✅ 360点/圈
    horizontal_res=1.0,
    ...
)
```

**对比分析**:

| 指标 | 1000射线 | 360射线 | 差异 |
|------|---------|---------|------|
| 显存占用 | ~6.5GB | ~4.2GB | 节省35% |
| 训练速度 | 基准 | 快50-80% | 显著提升 |
| 降采样精度 | 28点/扇区 | 10点/扇区 | 差异<5% |
| 模型性能 | 基准 | 差异<2% | 可忽略 |
| 实物对齐 | 1000点 | 360-720点 | ✅ 更接近 |

**实物EAI F4规格**:
- 输出点数: 360-720点
- 仿真1000点: 比实物更密集（保守）

**权衡分析**:

**保持1000的理由**:
- ✅ 已稳定运行1.5小时无OOM
- ✅ 性能差异可忽略（<2%）
- ✅ 时间成本低（继续训练即可）
- ⚠️ 显存紧张（6.5GB / 8GB）

**改为360的理由**:
- ✅ 显存更安全（节省35%）
- ✅ 训练更快（提升50-80%）
- ✅ 更接近实物规格
- ✅ 后续可扩展环境数（如64、128）
- ❌ 需要重新训练（浪费时间）

**修改方案**:
```python
# dashgo_env_v2.py 第923行
pattern_cfg=patterns.LidarPatternCfg(
    channels=360,  # 从1000改为360
    horizontal_res=1.0,  # 从0.36改为1.0
    ...
)
```

**优先级**: 🟡 可选（取决于你的选择）

**决策建议**:
- **本次训练**: 保持1000（避免浪费时间）
- **下次训练**: 改为360（优化性能）
