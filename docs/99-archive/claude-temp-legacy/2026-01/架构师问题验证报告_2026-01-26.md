## 问题1：action_smoothness 符号错误（奖励黑客漏洞）

### 架构师的主张

> "action_smoothness 的符号搞反了，权重 -0.01 × 负函数 = 正奖励，机器人在刷分！"

### 代码验证

**函数定义**（dashgo_env_v2.py 第563-565行）：
```python
def reward_action_smoothness(env: ManagerBasedRLEnv) -> torch.Tensor:
    diff = env.action_manager.action - env.action_manager.prev_action
    return -torch.sum(torch.square(diff), dim=1)  # 返回负值
```

**配置**（dashgo_env_v2.py 第1008-1011行）：
```python
action_smoothness = RewardTermCfg(
    func=reward_action_smoothness,
    weight=-0.01,  # ❌ 负权重
)
```

### 数学分析

**预期行为**（平滑度应该是惩罚项）：
```
最终奖励 = 负函数 × 正权重
         = -sum(diff²) × 0.01
         = -0.01 × sum(diff²)  ✅ 负数（惩罚）
```

**实际行为**（双重负号 = 正奖励）：
```
最终奖励 = 负函数 × 负权重
         = -sum(diff²) × (-0.01)
         = +0.01 × sum(diff²)  ❌ 正数（奖励！）
```

**具体影响**：
- 抖动差异 diff = 0.1 → reward = 0.01 × 0.01² = 0.0001
- 抖动差异 diff = 1.0 → reward = 0.01 × 1.0² = 0.01
- 抖动差异 diff = 2.0 → reward = 0.01 × 4.0 = 0.04

**结论**：机器人抖动越大，得分越高！

### 验证结果

✅ **架构师完全正确！**

**问题确认**：
1. ❌ 双重负号导致惩罚变奖励
2. ❌ 机器人通过"原地疯狂抖动轮子"刷分
3. ❌ 这是典型的"奖励黑客"（Reward Hacking）漏洞

**修复方案**：
```python
# 方案A：修改权重为正数（推荐）
action_smoothness = RewardTermCfg(
    func=reward_action_smoothness,
    weight=0.01,  # 从 -0.01 改为 0.01
)

# 方案B：修改函数返回正数，权重保持负数
def reward_action_smoothness(env: ManagerBasedRLEnv) -> torch.Tensor:
    diff = env.action_manager.action - env.action_manager.prev_action
    return torch.sum(torch.square(diff), dim=1)  # 去掉负号
```

## 问题2：shaping_distance 梯度消失

### 架构师的主张

> "std=2.0 太小，远处目标的 tanh 饱和，奖励接近0，梯度消失，机器人躺平"

### 代码验证

**函数实现**（dashgo_env_v2.py 第368-403行）：
```python
def reward_position_command_error_tanh(env, std: float, command_name: str, asset_cfg: SceneEntityCfg) -> torch.Tensor:
    """tanh距离奖励"""
    target_pos = env.command_manager.get_command(command_name)[:, :2]
    robot_pos = env.scene[asset_cfg.name].data.root_pos_w[:, :2]
    dist = torch.norm(target_pos - robot_pos, dim=1)
    return 1.0 - torch.tanh(dist / std)  # 公式
```

**配置**（dashgo_env_v2.py 第975-979行）：
```python
shaping_distance = RewardTermCfg(
    func=reward_position_command_error_tanh,
    weight=0.75,
    params={"std": 2.0, "command_name": "target_pose", "asset_cfg": SceneEntityCfg("robot")}
)
```

### 数学计算（std=2.0）

| 距离 | tanh(dist/2.0) | reward = 1-tanh | weighted = reward×0.75 |
|------|---------------|-----------------|----------------------|
| 2m   | 0.761594      | 0.238406        | **0.179**           |
| 4m   | 0.964028      | 0.035972        | **0.027**           |
| 6m   | 0.995055      | 0.004945        | **0.0037**          |
| 8m   | 0.999329      | 0.000671        | **0.0005**          |

**关键发现**：
- 距离 ≥ 6m 时，奖励 < 0.004
- 距离 ≥ 8m 时，奖励 < 0.001
- 四舍五入后显示为 **0.0000** ✅

**梯度分析**：
```
tanh 的导数：d(tanh x)/dx = 1 - tanh²(x)

当 dist = 6m, std = 2.0：
x = 6/2 = 3
tanh(3) ≈ 0.995
导数 = 1 - 0.995² ≈ 0.01（梯度几乎消失）
```

### 数学计算（如果 std=4.0，架构师建议）

| 距离 | tanh(dist/4.0) | reward = 1-tanh | weighted = reward×0.75 |
|------|---------------|-----------------|----------------------|
| 2m   | 0.462117      | 0.537883        | **0.403**           |
| 4m   | 0.761594      | 0.238406        | **0.179**           |
| 6m   | 0.905148      | 0.094852        | **0.071**           |
| 8m   | 0.964028      | 0.035972        | **0.027**           |

**改进效果**：
- 距离 6m 时，奖励从 0.0037 提升到 **0.071**（提升19倍！）
- 距离 8m 时，奖励从 0.0005 提升到 **0.027**（提升54倍！）
- 梯度明显增强，机器人能感受到远距离目标的"引力"

### 验证结果

✅ **架构师完全正确！**

**问题确认**：
1. ❌ std=2.0 导致远距离奖励几乎为0（6m以上 < 0.004）
2. ❌ tanh 函数进入饱和区，梯度消失
3. ❌ 日志显示 0.0000 不是bug，而是数值太小被四舍五入
4. ❌ 机器人在远处感受不到"引力"，选择"躺平"

**修复方案**：
```python
shaping_distance = RewardTermCfg(
    func=reward_position_command_error_tanh,
    weight=0.75,
    params={
        "std": 4.0,  # 从 2.0 改为 4.0（扩大吸引范围）
        "command_name": "target_pose",
        "asset_cfg": SceneEntityCfg("robot")
    }
)
```
