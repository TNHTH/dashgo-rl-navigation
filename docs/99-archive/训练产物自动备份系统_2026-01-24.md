# 训练产物自动备份系统

> **创建时间**: 2026-01-24 18:50:00
> **功能**: 自动管理训练产物（模型、TensorBoard事件）
> **状态**: ✅ 已部署

---

## 📋 系统概述

为了避免训练产物（模型文件、TensorBoard事件）污染代码仓库，我们建立了一套自动备份系统。

**核心原则**：
- ✅ 每次代码修改后自动备份旧训练产物
- ✅ 按日期和原因分类组织备份
- ✅ 清空 logs 目录为新训练准备
- ✅ 不提交训练产物到 Git

---

## 🛠️ 使用方法

### 方法1：手动执行备份脚本（推荐）

```bash
# 在项目根目录执行
./backup_training_artifacts.sh
```

**脚本功能**：
1. 自动检测 logs/ 目录中的训练产物
2. 创建按日期分类的备份目录
3. 分类备份：模型、TensorBoard事件、其他文件
4. 生成备份报告

**备份目录结构**：
```
logs_backup/
└── 2026-01-24/
    ├── 20260124_184950_reward_hacking_fixed/
    │   ├── models/          (model_*.pt 文件)
    │   ├── tensorboard/     (events.out.tfevents.* 文件)
    │   └── misc/            (rsl_rl/, git/ 等目录)
    ├── 20260124_190500_api_compatibility_fixed/
    └── ...
```

### 方法2：清空 logs 目录（快速）

```bash
# 备份后清空
rm -rf logs/*
```

## 📂 备份文件分类

### 1. 模型文件 (`models/`)

**文件模式**: `model_*.pt`

**说明**: PyTorch 模型检查点，包含完整的网络权重和优化器状态

**大小**: 约 4.2MB/个

**用途**:
- 恢复训练
- 评估模型性能
- 导出 ONNX 用于部署

### 2. TensorBoard 事件 (`tensorboard/`)

**文件模式**: `events.out.tfevents.*`

**说明**: TensorBoard 训练日志，包含损失、奖励、指标等

**用途**:
- 可视化训练曲线
- 分析训练过程
- 对比不同实验

**查看方法**：
```bash
tensorboard --logdir logs_backup/2026-01-24/20260124_184950_reward_hacking_fixed/tensorboard
```

### 3. 其他文件 (`misc/`)

**内容**:
- `rsl_rl/` - RSL-RL 训练器配置
- `git/` - Git 状态信息

## 🔧 脚本详解

### 脚本位置
```
/home/gwh/dashgo_rl_project/backup_training_artifacts.sh
```

### 核心功能

**1. 检测训练产物**
```bash
MODEL_COUNT=$(find "${LOGS_DIR}" -name "model_*.pt" | wc -l)
EVENT_COUNT=$(find "${LOGS_DIR}" -name "events.out.tfevents.*" | wc -l)
```

**2. 创建备份目录**
```bash
BACKUP_DIR="${BACKUP_ROOT}/${DATE_ONLY}/${TIMESTAMP}_<reason>"
mkdir -p "${MODELS_DIR}"
mkdir -p "${TENSORBOARD_DIR}"
mkdir -p "${MISC_DIR}"
```

**3. 分类备份文件**
```bash
# 模型文件
find "${LOGS_DIR}" -name "model_*.pt" -exec cp {} "${MODELS_DIR}/" \;

# TensorBoard 事件
find "${LOGS_DIR}" -name "events.out.tfevents.*" -exec cp {} "${TENSORBOARD_DIR}/" \;

# 其他文件
cp -r "${LOGS_DIR}/rsl_rl" "${MISC_DIR}/"
```

**4. 生成备份报告**
```
✅ 备份完成！
备份位置: /path/to/backup
备份统计:
  - 模型文件: 14 个
  - TensorBoard事件: 7 个
  - 其他文件: 2 项
```

## 🎓 最佳实践

### 1. 何时备份

**必须备份的情况**：
- ✅ 代码修改后（奖励函数、网络结构）
- ✅ 超参数调整后（学习率、环境数量）
- ✅ 修复bug后
- ✅ 训练异常终止后

**可选备份**：
- 定期备份（如每周一次）
- 实验性训练前

### 2. 备份命名建议

**描述原因，不要描述结果**：

✅ **好的命名**：
- `reward_hacking_fixed` - 修复奖励黑客
- `hyperparameter_tuned` - 超参数调优
- `initial_training` - 初始训练

❌ **不好的命名**：
- `backup_1` - 无意义
- `test_run` - 不明确
- `final_version` - 可能不是最终版本

### 3. 清理策略

**保留策略**：
- ✅ 保留所有备份（磁盘空间充足时）
- ✅ 按日期组织，方便查找

**删除策略**（磁盘不足时）：
- 🗑️ 删除最早的备份
- 🗑️ 只保留最近 1 个月的备份
- 🗑️ 删除明显失败的实验
