# DashGo 事故与复盘策略

> 创建时间: 2026-03-25

## 1. 事故记录分层

### GitHub Issue

负责当前问题的生命周期：

- 标题
- 优先级
- 状态
- 责任边界
- 关联 PR
- 验收标准

### 本地 `issues/`

负责深度材料：

- 终端日志
- 训练曲线
- 现场观察
- 原因分析
- 修复尝试
- 复盘结论

## 2. 何时写本地长篇记录

以下情况默认要写本地档案：

- 训练回归失败且需要保留多轮对比
- 实机 bringup 或 field test 出现复杂异常
- 架构整改需要保留长篇分析
- 自动化值守出现状态漂移、假运行或 safe pause 异常

## 3. 何时做复盘

以下情况默认触发 `retro-optimizer`：

- 一个长期任务结束
- 一次训练窗口结束
- 一次现场测试结束
- 出现流程级失误而不是单点 bug

## 4. 本地 `issues/` 的新定位

本目录不再承担“当前工作项唯一入口”。

新定位是：

- 事故档案库
- 长篇分析附件库
- 训练/部署/实机的证据库

当前工作项应优先进入 GitHub Issue，再在本地 `issues/` 或 `docs/` 写长篇附件。
