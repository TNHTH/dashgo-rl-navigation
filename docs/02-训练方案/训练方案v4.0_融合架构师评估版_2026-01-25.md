## 🎯 方案设计理念

### 核心原则
1. **保持v3_robust_nav的稳定性**（学习率1.5e-4，熵系数0.005）
2. **采纳架构师的专业建议**（课程学习、明确PPO定位）
3. **平衡学习效率和收敛速度**（解决shaping过低的问题）
4. **长期可行性**（为Sim2Real部署做准备）

## 📋 Phase 1: 基础配置（0-1000迭代）

### 1.1 训练配置
```yaml
# train_cfg_v2.yaml
runner:
  experiment_name: "dashgo_v4_curriculum"
  run_name: "phase1_close_range"
  max_iterations: 1000  # 第一阶段1000轮

algorithm:
  learning_rate: 1.5e-4
  entropy_coef: 0.005
  clip_param: 0.2
  schedule: "adaptive"
```

### 1.2 奖励函数（第一阶段：近距离训练）
```python
@configclass
class RewardsCfg_Phase1:
    """
    课程学习阶段一：近距离导航（0-3米目标）

    目标：让机器人快速学会"移动有奖励"的基本概念
    策略：提高引导权重，降低收敛难度
    """

    # [主线任务] 到达终点
    reach_goal = RewardTermCfg(
        func=mdp.terminations.is_command_close,
        params={"command_name": "target_pose", "threshold": 0.5},
        weight=100.0  # 终点奖励（不是2500那么夸张，但足够明确）
    )

    # [增强引导] 靠近目标（权重翻倍，解决0.5过低的问题）
    shaping_distance = RewardTermCfg(
        func=mdp.rewards.position_command_error_tanh,  # 使用tanh映射
        weight=1.0,  # 从0.5提升到1.0（阶段一特供）
        params={"std": 2.0, "command_name": "target_pose"}
    )

    # [保持引导] 速度奖励
    target_speed = RewardTermCfg(
        func=reward_target_speed,
        weight=1.0,
        params={"asset_cfg": SceneEntityCfg("robot")}
    )

    # [保持引导] 对准奖励
    facing_goal = RewardTermCfg(
        func=reward_facing_target,
        weight=0.1,
        params={
            "command_name": "target_pose",
            "asset_cfg": SceneEntityCfg("robot")
        }
    )

    # [关键新增] 动作平滑约束（采纳架构师建议）
    action_smoothness = RewardTermCfg(
        func=mdp.rewards.action_smoothness,
        weight=-0.01,  # 从0.0001提升到-0.01（提升100倍，但不是-0.05那么激进）
        params={}
    )

    # [移除] velodyne_style_reward（简化奖励架构，避免冲突）
    # velodyne_style_reward = RewardTermCfg(...)  # 暂时移除

    # [安全约束] 碰撞惩罚
    collision = RewardTermCfg(
        func=penalty_collision_force,
        params={"threshold": 10.0},  # 从1.0放宽到10.0（避免误触发，但不是100）
        weight=-50.0
    )

    # [生存] 归零
    alive_penalty = RewardTermCfg(func=mdp.rewards.is_alive, weight=0.0)
```

## 🎯 关键设计理念

### 1. 课程学习（采纳架构师建议）

**问题**：shaping_distance 0.5过低，可能导致收敛慢
**解决**：
- 阶段一（0-1000 iter）：权重1.0，目标范围0.5-3.0m
- 阶段二（1000-3000 iter）：权重0.5，目标范围0.5-8.0m
- 阶段三（3000-5000 iter）：权重0.3，进一步优化

**原理**：
> "先让机器人尝到甜头（近距离成功），再挑战长途奔袭（远距离导航）"

### 2. 明确PPO定位（采纳架构师建议）

**问题**：PPO不擅长长距离寻路
**解决**：
- 短期：目标范围限制（课程学习本身就是限制）
- 长期：PPO定义为Local Planner，配合ROS move_base全局规划

**原理**：
> "PPO只负责'走直线并避眼前障碍'，长距离寻路交给ROS move_base"

### 3. 动作平滑约束（采纳架构师建议）

**问题**：action_smoothness 0.0001几乎为0，导致Noise 17.30
**解决**：提升到-0.01（不是-0.05那么激进）

**原理**：
> "强平滑约束是解决Noise爆炸的关键，但-0.05可能让机器人不敢动，-0.01是平衡点"

### 4. 终点奖励明确（采纳架构师建议）

**问题**：终点信号不够明确
**解决**：新增100.0 reach_goal奖励（不是2500那么极端）

**原理**：
> "100.0足够大，让机器人知道'到达终点最重要'，但不会压倒一切导致Sparse奖励问题"

### 5. PhysX原生碰撞（采纳架构师建议）

**问题**：1.0阈值过于敏感
**解决**：提升到10.0（不是100.0那么极端）

**原理**：
> "对于圆盘形机器人，PhysX原生碰撞检测已经足够好且极快"
