# 第二章：操作系统安装（Ubuntu 20.04 LTS）

## 2.1 制作启动盘

### 2.1.1 下载Ubuntu镜像

```bash
# 官方下载地址
https://ubuntu.com/download/desktop

# 选择版本：Ubuntu 20.04.6 LTS (Focal Fossa)
# 文件名：ubuntu-20.04.6-desktop-amd64.iso
# 大小：~3.6GB
```

### 2.1.2 制作启动盘（Rufus - Windows）

1. **下载Rufus**: https://rufus.ie/
2. **插入USB盘**（≥8GB）
3. **运行Rufus**：
   - 设备：选择你的USB盘
   - 引导类型：GPT
   - 目标系统：UEFI（非CSM）
   - 文件系统：FAT32
   - 集簇大小：默认
4. **选择ISO镜像**：点击"选择"，浏览到Ubuntu ISO文件
5. **开始写入**：点击"开始"，等待完成（~10分钟）

### 2.1.3 制作启动盘（balenaEtcher - macOS/Linux）

1. **下载balenaEtcher**: https://www.balena.io/etcher/
2. **插入USB盘**（≥8GB）
3. **打开balenaEtcher**
4. **选择ISO镜像**
5. **选择目标驱动器**（USB盘）
6. **开始烧录**：点击"Flash!"，等待完成（~10分钟）

## 2.2 安装Ubuntu 20.04

### 2.2.1 启动到安装界面

1. **插入启动盘**到目标电脑
2. **开机**，立即进入BIOS（通常按F2、F12、或Del键）
3. **设置启动顺序**：USB → HDD
4. **保存并退出**（F10）
5. **选择"Install Ubuntu"**进入安装向导

### 2.2.2 分区方案（推荐）

**方案A：自动分区（新手推荐）**


**方案B：手动分区（高级用户）**

| 挂载点 | 大小 | 类型 | 说明 |

| `/boot/efi` | 512MB | FAT32 | EFI系统分区 |
| `swap` | 16GB | swap | 交换空间（=内存大小） |
| `/` | 50GB | ext4 | 根分区 |
| `/home` | 剩余空间 | ext4 | 用户数据分区 |

# 第六章：基础概念讲解

## 6.1 什么是强化学习（RL）？

### 6.1.1 强化学习的基本概念

**强化学习**是一种机器学习方法，通过**试错**和**奖励**机制训练智能体（Agent）在环境中做出最优决策。

**核心要素**：
- **Agent（智能体）**：机器人，负责做出决策
- **Environment（环境）**：机器人所处的世界
- **State（状态）**：环境当前的情况
- **Action（动作）**：Agent可以做的事情
- **Reward（奖励）**：环境对Agent动作的反馈

### 6.1.2 生活中的例子

**训练小狗**：
```
State: 小狗看到飞盘
Action: 跳起来接住 / 无动于衷
Reward:
  - 接住了：奖励骨头（正奖励）
  - 没接：没有骨头（零奖励）
  - 咬到人：惩罚（负奖励）

目标：学会接飞盘以获得更多骨头
```

**DashGo机器人导航**：
```
State: LiDAR传感器数据 + 目标位置
Action: 前进速度 + 转向角速度
Reward:
  - 到达目标：+2000分（大奖）
  - 靠近目标：+0.75分（引导）
  - 碰到障碍：-200分（惩罚）
  - 动作平滑：-0.01分（防抖动）

目标：学会避开障碍物到达目标
```

### 6.1.3 强化学习 vs 传统方法

| 对比项 | 强化学习 | 传统方法（PID/DWA） |
|--------|---------|-------------------|
| **规则** | 自动学习 | 手工设计 |
| **适应性** | 强（自动优化） | 弱（固定参数） |
| **复杂环境** | 表现好 | 表现一般 |
| **训练成本** | 高（需大量训练） | 低（直接使用） |
| **维护成本** | 低（自适应） | 高（手动调参） |

## 6.2 什么是PPO算法？

### 6.2.1 PPO全称

**PPO** = **Proximal Policy Optimization**（近端策略优化）

### 6.2.2 为什么选择PPO？

**优点**：
1. **稳定性好**：不容易崩溃
2. **样本效率高**：比其他算法需要更少的训练数据
3. **实现简单**：代码容易理解和调试
4. **性能优秀**：在很多任务上达到或超过人类水平

**缺点**：
1. **训练时间长**：需要大量计算资源
2. **超参数敏感**：参数设置不当会影响性能

### 6.2.3 PPO工作原理（简化版）

```
初始化：随机策略（机器人随机乱动）
循环：
  1. 机器人按照当前策略行动（与环境交互）
  2. 收集经验（状态、动作、奖励）
  3. 计算每个动作的价值（好的动作还是坏的动作？）
  4. 更新策略（多做好的动作，少做坏的动作）
  5. 重复直到收敛（机器人学会最优策略）
```

**比喻**：就像玩游戏
```
初期：乱按键，不知道怎么玩
中期：发现某些操作能得分，开始记住
后期：掌握技巧，获得高分

PPO的优势：
  - 不会"走极端"（限制策略更新幅度）
  - 持续改进（每次迭代都比上次好一点点）
  - 充分利用经验（重复使用训练数据）
```

## 6.3 什么是Isaac Sim？

### 6.3.1 Isaac Sim简介

**Isaac Sim**是NVIDIA开发的机器人仿真器，基于**NVIDIA Omniverse**平台。

**核心功能**：
- **物理仿真**：真实的物理引擎（PhysX 5）
- **渲染**：基于光线追踪的高保真渲染
- **传感器仿真**：LiDAR、相机、IMU等
- **并行训练**：同时训练数千个机器人

### 6.3.2 为什么需要仿真？

**实物训练的问题**：
1. **成本高**：机器人可能损坏
2. **速度慢**：实物测试耗时长
3. **危险**：机器人失控可能伤人
4. **难以复现**：环境变化导致结果不一致

**仿真的优势**：
1. **成本低**：虚拟机器人不会坏
2. **速度快**：可以加速时间、并行训练
3. **安全**：虚拟环境不会伤人
4. **可控**：可以重复相同的实验

### 6.3.3 仿真与实物的差距（Sim2Real）

**Sim2Real Gap**：仿真训练的策略在实物上表现不好

**原因**：
- 仿真物理引擎不完美
- 传感器模型不准确
- 环境噪声不同
- 机器人制造误差

**解决方案**：
1. **参数对齐**：仿真参数严格匹配实物
2. **域随机化**：随机化仿真环境，增加泛化能力
3. **传感器噪声**：模拟真实传感器的噪声
4. **渐进部署**：先在安全环境测试，再逐步增加难度

## 6.4 什么是ROS？

**ROS** = **Robot Operating System**（机器人操作系统）

**核心功能**：
- **节点间通信**：不同的程序可以互相通信
- **设备驱动**：统一的硬件接口

### 6.4.2 ROS核心概念

**节点（Node）**：

**话题（Topic）**：
```
节点间通信的管道
例如：
  /scan：LiDAR数据流
  /cmd_vel：速度命令
  /odom：里程计数据
```

**消息（Message）**：
```
话题上传递的数据格式
例如：
  sensor_msgs/LaserScan：LiDAR消息
  geometry_msgs/Twist：速度消息
```

### 7.2.3 geo_nav_policy.py - 轻量级网络

**作用**：实现轻量级CNN+MLP网络架构（v3.1）

**为什么叫"轻量级"？**
```
传统方案：
  参数量：500K
  显存：150MB

  适配性：需要优化才能部署到Jetson Nano

v3.1方案：

  显存：100MB（⬇️ 33%）
  推理速度：80Hz（⬆️ 60%）
  适配性：✅ 可直接部署到Jetson Nano 4GB
```

**网络架构**：
```python
class GeoNavPolicy(ActorCritic):
    """轻量级几何导航策略"""
    
    def __init__(self, num_actor_obs, num_critic_obs, ...):
        # [Geo-Encoder] 几何特征提取
        self.geo_encoder = nn.Sequential(
            nn.Conv1d(1, 16, kernel_size=5, stride=2),  # 72 → 34
            nn.LayerNorm(16),
            nn.ELU(),
            nn.Conv1d(16, 32, kernel_size=3, stride=2),  # 34 → 16
            nn.LayerNorm(32),
            nn.ELU(),
            nn.Flatten(),
            nn.Linear(544, 64),  # 32 * 17 = 544
            nn.LayerNorm(64),
            nn.ELU(),
        )
        
        # [Fusion Layer] 特征融合
        self.fusion_layer = nn.Sequential(
            nn.Linear(64 + 30, 128),  # 64(LiDAR) + 30(其他)
            nn.LayerNorm(128),
            nn.ELU(),
        )
        
        # [Memory Layer] 时序记忆
        self.memory_layer = nn.Sequential(
            nn.Linear(128, 128),
            nn.LayerNorm(128),
            nn.ELU(),
        )
        
        # [Actor Head] 轻量级动作输出
        self.actor_mean = nn.Sequential(
            nn.Linear(128, 64),
            nn.LayerNorm(64),
            nn.ELU(),
            nn.Linear(64, 2),  # [v_norm, w_norm]
        )
        
        # [Critic Head] 强力值函数
        self.critic = nn.Sequential(
            nn.Linear(246, 512),
            nn.LayerNorm(512),
            nn.ELU(),
            nn.Linear(512, 256),
            nn.LayerNorm(256),
            nn.ELU(),
            nn.Linear(256, 128),
            nn.LayerNorm(128),
            nn.ELU(),
            nn.Linear(128, 1),  # 状态价值
        )
    
    def forward(self, obs_dict):
        """前向传播"""
        # 1. 提取LiDAR历史（3帧 × 72维 = 216维）
        lidar_history = obs_dict["lidar"]  # shape: (N, 216)
        lidar_history = lidar_history.reshape(N, 3, 72)  # (N, 3, 72)
        
        # 2. Geo-Encoder
        geo_features = self.geo_encoder(lidar_history)  # (N, 64)
        
        # 3. 拼接其他观测
        goal_vec = obs_dict["goal_vec"]  # (N, 3)
        last_action = obs_dict["last_action"]  # (N, 2)
        robot_state = obs_dict["robot_state"]  # (N, 25)
        other_features = torch.cat([goal_vec, last_action, robot_state], dim=-1)  # (N, 30)
        
        # 4. Fusion Layer
        fused = self.fusion_layer(torch.cat([geo_features, other_features], dim=-1))  # (N, 128)
        
        # 5. Memory Layer
        memory = self.memory_layer(fused)  # (N, 128)
        
        # 6. Actor Head（动作输出）
        action_mean = self.actor_mean(memory)  # (N, 2) ∈ [-1, 1]
        
        # 7. Critic Head（状态价值）
        value = self.critic(obs_dict["policy"])  # (N, 1)
        
        return action_mean, value
```

```python
# ✅ 新方案（v3.1）：三层防护

# 3. Orthogonal Init（正交初始化）
nn.init.orthogonal_(self.fc.weight, gain=np.sqrt(2))
```

### 8.1.2 LiDAR历史（216维）

**为什么需要历史？**
```
单帧LiDAR（72维）：
  - 只能知道当前障碍物位置
  - 无法判断障碍物运动趋势
  - 无法判断机器人运动状态

3帧历史（216维）：
  - 可以判断障碍物是静止/运动
  - 可以判断机器人是前进/后退
  - 提供短时记忆（类似短期记忆）
```

**实现方式**：
```python
# 在环境中维护历史缓冲区
self.history_buffer = []

# 每个时间步更新
current_lidar = process_stitched_lidar(env)  # 72维
self.history_buffer.append(current_lidar)

# 保持最近3帧
if len(self.history_buffer) > 3:
    self.history_buffer.pop(0)

# 拼接历史
lidar_history = np.concatenate(self.history_buffer)  # 216维
```

### 8.1.3 目标向量（3维）

**为什么不直接用坐标？**
```
原始坐标（x, y）：
  - 依赖于坐标系原点
  - 距离目标远时数值很大
  - 距离目标近时数值很小
  - 网络难以学习

目标向量（distance, sinθ, cosθ）：
  - distance：归一化距离
  - sinθ, cosθ：归一化角度（避免-π~π的不连续）
  - 数值范围固定，易于学习
```

**计算方法**：
```python
def compute_goal_vector(robot_pos, robot_yaw, goal_pos):
    """计算目标向量"""
    # 1. 计算相对位置
    dx = goal_pos[0] - robot_pos[0]
    dy = goal_pos[1] - robot_pos[1]
    
    # 2. 计算距离和角度
    distance = np.sqrt(dx**2 + dy**2)
    angle = np.arctan2(dy, dx) - robot_yaw
    
    # 3. 归一化角度（sinθ, cosθ）
    angle_sin = np.sin(angle)
    angle_cos = np.cos(angle)
    
    return [distance, angle_sin, angle_cos]
```

### 8.2.2 动作转换（归一化 → 真实速度）

```python
def process_action(action):
    """将归一化动作转换为真实速度"""
    # 1. 读取归一化动作
    v_norm = action[0]  # ∈ [-1, 1]
    w_norm = action[1]  # ∈ [-1, 1]
    
    # 2. 反归一化
    max_v = MOTION_CONFIG["max_lin_vel"]  # 0.3 m/s
    max_w = MOTION_CONFIG["max_ang_vel"]  # 1.0 rad/s
    
    v = v_norm * max_v  # ∈ [-0.3, 0.3]
    w = w_norm * max_w  # ∈ [-1.0, 1.0]
    
    # 3. 速度限制（硬裁断）
    v = np.clip(v, -max_v, max_v)
    w = np.clip(w, -max_w, max_w)
    
    # 4. 差速驱动转换
    v_left = (v - w * track_width / 2.0) / wheel_radius
    v_right = (v + w * track_width / 2.0) / wheel_radius
    
    return v_left, v_right
```

### 8.2.3 动作平滑

**为什么需要平滑？**
```
直接输出：
  action_0 = [0.5, 0.0]    # 前进
  action_1 = [-0.5, 0.0]   # 立即后退
  结果：电机突变，机器人抖动

平滑后：
  action_0 = [0.5, 0.0]
  action_1 = [0.4, 0.0]    # 平滑过渡
  action_2 = [0.3, 0.0]
  action_3 = [0.2, 0.0]
  result：运动平滑，无抖动
```

**实现方式**：
```python
# 在环境中维护上一帧动作
self.last_action = np.zeros(2)

# 计算动作变化率
action_rate = action - self.last_action

# 惩罚大幅变化
penalty = -0.01 * np.linalg.norm(action_rate)

# 更新上一帧动作
self.last_action = action
```

```python
    """DashGo ROS参数配置类"""
    
    @classmethod
    def from_yaml(cls, yaml_path="dashgo/EAI驱动/dashgo_bringup/config/my_dashgo_params.yaml"):
        """从YAML文件加载参数"""
        with open(yaml_path, 'r') as f:
            params = yaml.safe_load(f)
        
        # 提取物理参数
        physical = DashGoPhysicalSpecs(
            wheel_diameter=params.get("wheel_diameter", 0.1264),
            wheel_track=params.get("wheel_track", 0.3420),
        )
        
        # 提取运动参数
        motion = DashGoMotionSpecs(
            max_lin_vel=0.3,
            max_ang_vel=1.0,
            max_lin_acc=1.0,
            max_ang_acc=0.6,
        )
        
        return cls(physical=physical, motion=motion, ...)
```

# 第十二章：参数调优指南

## 12.1 核心参数调优

### 12.1.1 学习率调优

**作用**：控制网络更新步长

**症状诊断**：
```python
# [症状1] 学习率太高
奖励曲线剧烈震荡
Mean reward:
  Iter 100: 500.2
  Iter 101: -234.1  (突然下降)
  Iter 102: 678.3   (突然上升)
  Iter 103: -123.5

# 解决：降低学习率
learning_rate: 3.0e-4 → 1.0e-4

# [症状2] 学习率太低
奖励曲线几乎不上升
Mean reward:
  Iter 100: 15.3
  Iter 500: 18.7   (400轮只涨了3.4)
  Iter 1000: 20.1

# 解决：提高学习率
learning_rate: 3.0e-4 → 5.0e-4

# [症状3] 学习率刚刚好
奖励曲线平稳上升
Mean reward:
  Iter 100: 85.7
  Iter 200: 234.1
  Iter 300: 456.8
  Iter 400: 678.2

# 保持不变
learning_rate: 3.0e-4 ✅
```

**调优策略**：
```
初始值：3.0e-4（PPO标准值）

调整规则：
- 奖励震荡（方差大） → 降低学习率（÷2）
- 收敛太慢（斜率小） → 提高学习率（×2）
- 训练稳定且收敛快 → 保持不变

调整范围：
- 最小值：1.0e-5（再小可能不收敛）
- 最大值：1.0e-3（再大可能不稳定）
```

### 12.1.2 熵系数调优

**作用**：控制探索程度

**症状诊断**：
```python
# [症状1] 熵系数太高（过度探索）
机器人行为：随机乱动，像"喝醉了"
Mean reward: 长期保持在0附近

# 解决：降低熵系数
entropy_coef: 0.01 → 0.005

# [症状2] 熵系数太低（探索不足）
机器人行为：过早收敛到局部最优
表现：每次都是相同的路线，即使有更优路径

# 解决：提高熵系数
entropy_coef: 0.01 → 0.02

# [症状3] 熵系数刚刚好
机器人行为：有探索也有利用
表现：成功率持续上升

# 保持不变
entropy_coef: 0.01 ✅
```

**调优策略**：
```
初始值：0.01（PPO标准值）

调整规则：
- 过度探索（随机乱动） → 降低熵系数（÷2）
- 探索不足（重复路径） → 提高熵系数（×2）
- 平衡探索/利用 → 保持不变

调整范围：
- 最小值：0.001（再小几乎不探索）
- 最大值：0.05（再大纯随机）
```

### 12.1.3 网络架构调优

**Actor vs Critic不平衡**：
```python
# [症状] Critic太弱
value_function_loss: 持续很高，不收敛
Mean reward: 波动大

# 解决：增强Critic
critic_hidden_dims: [256, 128] → [512, 256, 128]

# [症状] Actor太弱
action: 几乎不变，总是输出同一个动作

# 解决：增强Actor
actor_hidden_dims: [64, 32] → [128, 64]

# [症状] 刚刚好
训练稳定，收敛快

# 保持不变
actor_hidden_dims: [128, 64] ✅
critic_hidden_dims: [512, 256, 128] ✅
```

**非对称架构优势**：
```
为什么Actor小、Critic大？

Actor（动作输出）：
- 目标：选择动作
- 需要：轻量、快速（部署友好）
- 参数：128, 64（轻量级）

Critic（价值评估）：
- 目标：评估状态价值
- 需要：准确、全面
- 参数：512, 256, 128（强力网络）

优势：
1. Actor小 → 推理快 → 适配Jetson Nano
2. Critic大 → 评估准 → 训练稳定
3. 非对称设计 → 优化目标明确
```

## 13.2 常见问题诊断

### 13.2.1 诊断工具

```python
# diagnose_training.py - 训练诊断工具

import re
import numpy as np

def diagnose_training(log_file):
    """诊断训练问题"""
    
    # 读取日志
    with open(log_file, 'r') as f:
        lines = f.readlines()
    
    # 提取关键指标
    iterations = []
    rewards = []
    episode_lengths = []
    value_losses = []
    
    for line in lines:
        if "Iteration:" in line and "Mean reward" in line:
            iter_num = int(re.search(r"Iteration:\s+(\d+)", line).group(1))
            mean_reward = float(re.search(r"Mean reward:\s+([\-\d\.]+)", line).group(1))
            mean_ep_len = float(re.search(r"Mean episode length:\s+([\d\.]+)", line).group(1))
            value_loss = float(re.search(r"Mean value_function loss:\s+([\-\d\.]+)", line).group(1))
            
            iterations.append(iter_num)
            rewards.append(mean_reward)
            episode_lengths.append(mean_ep_len)
            value_losses.append(value_loss)
    
    # 诊断
    print("════════════════════════════════════════")
    print("训练诊断报告")
    print("════════════════════════════════════════")
    
    # [1] 奖励趋势
    print("\n[1] 奖励趋势分析:")
    if len(rewards) > 100:
        early_reward = np.mean(rewards[:100])
        late_reward = np.mean(rewards[-100:])
        improvement = late_reward - early_reward
        
        print(f"  初期平均奖励: {early_reward:.2f}")
        print(f"  后期平均奖励: {late_reward:.2f}")
        print(f"  改进幅度: {improvement:.2f}")
        
        if improvement > 0:
            print(f"  ✅ 奖励上升{improvement:.2f}，训练有效")
        else:
            print(f"  ❌ 奖励下降或停滞，需要调优")
    
    # [2] Episode长度趋势
    print("\n[2] Episode长度分析:")
    if len(episode_lengths) > 100:
        early_len = np.mean(episode_lengths[:100])
        late_len = np.mean(episode_lengths[-100:])
        
        print(f"  初期平均长度: {early_len:.1f}步")
        print(f"  后期平均长度: {late_len:.1f}步")
        
        if late_len > early_len:
            print(f"  ✅ Episode长度增加，机器人存活更久")
        else:
            print(f"  ⚠️ Episode长度减少，可能有问题")
    
    # [3] 值函数损失
    print("\n[3] 值函数损失分析:")
    if len(value_losses) > 100:
        recent_losses = value_losses[-100:]
        inf_count = sum(1 for x in recent_losses if x > 1e6)
        
        print(f"  最近100轮平均损失: {np.mean(recent_losses):.2f}")
        print(f"  inf/nan出现次数: {inf_count}")
        
        if inf_count > 0:
            print(f"  ❌ 检测到梯度爆炸！需要检查v3.1修复")
        else:
            print(f"  ✅ 值函数损失正常")
    
    # [4] 训练稳定性
    print("\n[4] 训练稳定性分析:")
    if len(rewards) > 100:
        reward_std = np.std(rewards[-100:])
        print(f"  奖励标准差: {reward_std:.2f}")
        
        if reward_std < 50:
            print(f"  ✅ 训练稳定")
        elif reward_std < 150:
            print(f"  ⚠️ 训练略有波动")
        else:
            print(f"  ❌ 训练不稳定，考虑降低学习率")

if __name__ == "__main__":
    import sys
    diagnose_training(sys.argv[1])
```

**症状**：

**原因**：
- 缺少LayerNorm（梯度爆炸）
- 输入未截断（Inf/NaN传播）
- Critic网络太弱（估值不准）

**解决方案**（v3.1已修复）：
```python
# ✅ 三层防护

# 1. LayerNorm（所有网络层后）
self.fc = nn.Linear(64, 128)
self.ln = nn.LayerNorm(128)

# 2. Input Clamp（输入截断）
x = torch.clamp(x, -10.0, 10.0)

# 3. Orthogonal Init（正交初始化）
nn.init.orthogonal_(self.fc.weight, gain=np.sqrt(2))
```

# 第十五章：模型导出

## 15.1 导出格式选择

### 15.1.1 PyTorch vs TorchScript vs ONNX

| 格式 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **PyTorch (.pt)** | 简单直接 | 需要PyTorch环境 | ⭐⭐⭐ |
| **TorchScript (.pt)** | 无需PyTorch，推理快 | 不支持动态图 | ⭐⭐⭐⭐⭐ |
| **ONNX (.onnx)** | 跨平台，TensorRT加速 | 转换复杂 | ⭐⭐⭐⭐ |

**推荐**：**TorchScript**（本项目使用）

**原因**：
1. 无需完整的PyTorch环境
2. 推理速度快（80Hz+）
3. 适配Jetson Nano
4. 转换简单

### 15.1.2 导出脚本

**export_torchscript.py**：
```python
#!/usr/bin/env python3
"""
模型导出脚本：将PyTorch checkpoint导出为TorchScript
"""

import torch
from geo_nav_policy import GeoNavPolicy
from dashgo_env_v2 import DashgoEnvCfg

def export_model(checkpoint_path, output_path):
    """导出模型为TorchScript"""
    
    # 1. 加载checkpoint
    print(f"[1/5] 加载checkpoint: {checkpoint_path}")
    checkpoint = torch.load(checkpoint_path, map_location="cpu")
    
    # 2. 创建模型
    print("[2/5] 创建模型")
    model = GeoNavPolicy(
        num_actor_obs=246,
        num_critic_obs=246,
        action_dim=2,
    )
    
    # 3. 加载权重
    print("[3/5] 加载权重")
    model.load_state_dict(checkpoint["model_state_dict"])
    model.eval()
    
    # 4. 转换为TorchScript
    print("[4/5] 转换为TorchScript")
    example_input = torch.randn(1, 246)  # 示例输入
    
    try:
        scripted_model = torch.jit.script(model)
        scripted_model(example_input)  # 验证
    except Exception as e:
        print(f"❌ TorchScript转换失败: {e}")
        return False
    
    # 5. 保存模型
    print(f"[5/5] 保存模型: {output_path}")
    scripted_model.save(output_path)
    
    # 验证
    loaded_model = torch.jit.load(output_path)
    output = loaded_model(example_input)
    print(f"✅ 验证成功！输出shape: {output.shape}")
    
    return True

if __name__ == "__main__":
    import sys
    
    checkpoint_path = sys.argv[1] if len(sys.argv) > 1 else "logs/dashgo_v5_auto/model_9000.pt"
    output_path = sys.argv[2] if len(sys.argv) > 2 else "models/policy_torchscript.pt"
    
    export_model(checkpoint_path, output_path)
```

```python
def lidar_callback(self, msg):
```

```python
# safety_filter.py - 三层防护
def filter(self, action, observation):
    v, w = action
    
    # [第一层] 倒车禁止
    if v < 0:
        return [0.0, 0.0]
    
    # [第二层] 碰撞检测
    if self.detect_collision(observation):
        return [0.0, 0.0]
    
    # [第三层] 线性衰减
    distance = self.min_distance(observation)
    if distance < 0.3:
        v *= distance / 0.3
    
    return [v, w]
```
