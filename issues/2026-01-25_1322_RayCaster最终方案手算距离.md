## 根本原因

### 架构师的诊断

> "报错 `AttributeError: 'RayCasterData' object has no attribute 'ranges'` 表明：Isaac Lab 的 `RayCaster` 底层数据结构并不直接提供'距离（ranges）'这个属性，它只提供'击中点（hits）'的世界坐标。"

**技术细节**：

1. **Isaac Lab 的物理真实**：
   - RayCaster 不像 ROS 驱动那样封装好的 `.ranges` 属性
   - 它更加"物理"，直接提供光线打在墙上的 XYZ 坐标
   - 需要自己计算距离（欧几里得距离）

2. **可用的属性**：
   - ✅ `sensor.data.ray_hits_w` - 击中点世界坐标 [N, M, 3]
   - ✅ `sensor.data.pos_w` - 传感器位置坐标 [N, 3]
   - ❌ `sensor.data.ranges` - 不存在

3. **为什么需要手算**：
   - Isaac Sim 的设计理念是"物理真实"
   - 给你的是光线击中点的世界坐标
   - 距离需要自己算：`distance = ||hit_point - sensor_origin||`

## 解决方案

### 架构师最终方案（v3.0）- 手算欧几里得距离

**核心思想**：使用向量运算计算两点间距离

```python
def process_lidar_ranges(env: ManagerBasedRLEnv, sensor_cfg: SceneEntityCfg) -> torch.Tensor:
    """
    [架构师修正 2026-01-25 v3.0 最终版] 处理 RayCaster 激光雷达数据
    """
    # 1. 获取传感器对象
    sensor = env.scene[sensor_cfg.name]

    # 2. 获取坐标数据
    ray_hits_w = sensor.data.ray_hits_w  # [num_envs, num_rays, 3]
    sensor_pos_w = sensor.data.pos_w      # [num_envs, 3]

    # 3. 计算相对向量 (Hit - Origin)
    # 使用 unsqueeze(1) 将 pos_w 从 [N, 3] 变为 [N, 1, 3] 以便广播减法
    rel_vec = ray_hits_w - sensor_pos_w.unsqueeze(1)

    # 4. 计算欧几里得距离 (L2 Norm)
    # 结果形状: [num_envs, num_rays]
    depths = torch.norm(rel_vec, dim=-1)

    # 5. 数据清洗与归一化
    max_range = 12.0
    depths = torch.nan_to_num(depths, nan=max_range, posinf=max_range, neginf=0.0)
    depths = torch.clamp(depths, min=0.0, max=max_range)

    # 6. 归一化到 [0, 1] 区间
    depths_normalized = depths / max_range

    # 7. 降采样到36个扇区
    num_sectors = 36
    batch_size, num_rays = depths_normalized.shape

    if num_rays % num_sectors == 0:
        depth_sectors = depths_normalized.view(batch_size, num_sectors, -1).min(dim=2)[0]
    else:
        depth_sectors = depths_normalized

    return depth_sectors
```

### 关键改进

1. **使用最基础的物理数据**：
   - `ray_hits_w` - 击中点坐标（绝对存在）
   - `pos_w` - 传感器位置（绝对存在）

2. **向量运算计算距离**：
   ```python
   rel_vec = ray_hits_w - sensor_pos_w.unsqueeze(1)  # 相对向量
   depths = torch.norm(rel_vec, dim=-1)              # L2 范数
   ```

3. **鲁棒性处理**：
   - `torch.nan_to_num` - 处理 NaN/Inf
   - `torch.clamp` - 限制在有效范围
   - 逻辑闭环：未击中物体时，hit_point 在射线末端，距离自然就是 max_range
