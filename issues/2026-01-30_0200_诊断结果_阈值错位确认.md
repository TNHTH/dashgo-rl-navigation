### 3. reward_near_goal 函数实现

**位置**: `dashgo_env_v2.py:790-800`

```python
def reward_near_goal(env, command_name, threshold, asset_cfg):
    # 计算距离
    command_term = env.command_manager._terms[command_name]
    target_pos_w = command_term.pose_command_w[:, :2]
    robot_pos = torch.nan_to_num(env.scene[asset_cfg.name].data.root_pos_w[:, :2])

    dist = torch.norm(target_pos_w - robot_pos, dim=-1)

    # 返回：距离 < 阈值 → 1.0，否则 → 0.0
    return (dist < threshold).float()
```

**关键发现**：
- 返回类型：**bool转float**（0.0或1.0）
- 不是连续奖励，是稀疏的二元奖励

## ❌ 问题确认：阈值错位

### 对比表

| 组件 | 阈值 | 触发难度 | 实际效果 |
|------|------|---------|----------|
| **Terminations** | 1.0m | 容易（宽松） | 机器人到达1m→episode结束 |
| **Rewards** | 0.25m | 困难（严格）| 需要到达0.25m→才给100分 |

### 时序分析

```
机器人运动轨迹：
起点 → 1.5m → 1.0m → 0.5m → 0.3m → 0.2m
       ↓      ↓      ↓      ↓      ↓
       继续   继续   [触发终止]  X      X
                    episode结束
                    reward=0.0
```

**关键时刻**：
- 距离 = 1.0m → **触发终止**，episode结束
- 此时距离还远大于0.25m → **没触发奖励**
- 结果：`Episode_Reward/reach_goal = 0.0000`

## 🔬 为什么训练还能进行？

### 终止率高的原因

虽然`reach_goal=0`，但终止率有78%，原因是：

1. **Time-out终止**：30秒时间到
2. **Collision终止**：撞墙
3. **Out-of-bounds**：越界
4. **Base-height/Bad-velocity**：其他失败条件

### 为什么价值函数崩溃？

```
永远拿不到reach_goal奖励(0分)
    ↓
价值函数无法估计"到达"的价值
    ↓
Value Loss爆炸（3519）
    ↓
策略梯度无方向，保持高熵（6.17）
    ↓
机器人随机乱跑
```

---

## 💡 解决方案

### 方案A：统一阈值（最简单）⭐⭐⭐⭐⭐

**核心思想**：让奖励阈值 >= 终止阈值

**修改 `dashgo_env_v2.py:1302-1310`**：

```python
reach_goal = RewardTermCfg(
    func=reward_near_goal,
    weight=100.0,
    params={
        "command_name": "target_pose",
        "threshold": 1.0,  # ✅ 从0.25m改为1.0m（与终止一致）
        "asset_cfg": SceneEntityCfg("robot")
    }
)
```

**效果**：
- 机器人到达1.0m时，先拿到100分奖励
- 然后触发终止，episode结束
- 结果：`Episode_Reward/reach_goal > 0`

**优点**：
- ✅ 最小修改（只改1个数字）
- ✅ 风险最低
- ✅ 立即见效

---

### 方案B：反向修改（更严格）⭐⭐⭐

**核心思想**：让终止阈值 <= 奖励阈值

**修改 `dashgo_env_v2.py:1428-1435`**：


**缺点**：
- ⚠️ 训练难度增加（阈值更严）
- ⚠️ 可能降低成功率

---

### 方案C：双重奖励（最稳健）⭐⭐⭐⭐

**核心思想**：保留0.25m的精确奖励，但添加1.0m的"接近奖励"

**修改 `dashgo_env_v2.py:1287-1320`**：


**效果**：
- 到达1.0m → 先拿10分（接近奖励）
- 继续靠近到0.25m → 再拿100分（精确奖励）
- 触发终止

**优点**：
- ✅ 提供持续引导
- ✅ 保持停车精度
- ✅ 奖励更丰富

## ⚠️ 关键警告

### 不要执行的修改

   - 权重100.0 vs 5.0失衡
   - parking_bonus极难触发

2. ❌ **不要用KL自适应**
   - 当前Value Loss=3519（系统崩溃）
   - KL自适应可能让LR→0，训练停滞
   - 应该先用固定LR

3. ❌ **不要降低learning_rate**
   - 当前问题不是学习率过高
   - 降低LR会让训练更慢
