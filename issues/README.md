# DashGo 本地 Issues 目录说明

> 创建时间: 2026-03-25
> 目录作用: 长篇问题档案 / 事故复盘 / 训练分析附件库

## 1. 当前定位

本目录不再承担“当前工作项唯一入口”。

当前工作项主入口已经切换为 GitHub Issue；本目录的角色是：

- 长篇问题档案
- 事故复盘
- 训练与评估对比记录
- 现场 bringup / field test 附件
- 架构分析与深度诊断材料

## 2. 什么时候写到这里

以下情况建议写本地 `issues/` 文档：

1. GitHub Issue 无法承载完整终端日志、训练曲线或长篇分析
2. 实机 bringup、导航测试、rosbag 复盘需要保留证据
3. 训练回归需要多轮对比、参数分析与实验结论
4. 架构整改需要保留详细 reasoning、合同和取舍

## 3. 与 GitHub Issue 的关系

推荐工作流：

1. GitHub 创建当前工作项
2. 如需长篇分析，在本目录新建文档
3. 在 GitHub Issue / PR 中链接该文档
4. 文档标题区回链 GitHub Issue / PR 编号

## 4. 命名建议

推荐沿用当前目录已有风格：

```text
YYYY-MM-DD_HHMM_问题主题.md
```

例如：

```text
2026-03-25_1930_autoresearch-safe-pause状态漂移复盘.md
```

## 5. 不要把这里当成什么

- 不要把这里当作 GitHub Issue 的替代品
- 不要把这里当作 PR 审查流的替代品
- 不要把“待办事项状态”只写在这里而不回填 GitHub
