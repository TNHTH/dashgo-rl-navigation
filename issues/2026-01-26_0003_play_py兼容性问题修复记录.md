## 问题1: OnPolicyRunner.get_observations() 不存在

### 错误信息

```
AttributeError: 'ManagerBasedRLEnv' object has no attribute 'get_observations'
```

### 问题分析

**根本原因**: Isaac Lab 0.46.4移除了`get_observations()`方法

**发生位置**: `OnPolicyRunner.__init__()` 内部调用

**API变化**:
- 旧版: `env.get_observations()` 直接返回观测
- 新版: 使用`env.step()`和`env.reset()`的返回值

### 解决方案

**架构师建议**: 完全绕过`OnPolicyRunner`，直接使用`ActorCritic`网络

**实施步骤**:
1. 从`rsl_rl.modules`导入`ActorCritic`类
2. 手动构建网络（从train_cfg_v2.yaml读取参数）
3. 直接加载checkpoint权重
4. 使用`policy.act_inference()`推理

**关键代码**:
```python
from rsl_rl.modules import ActorCritic

# 手动构建网络
policy = ActorCritic(
    num_actor_obs=num_obs,
    num_critic_obs=num_obs,
    num_actions=num_actions,
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
).to(device)

# 加载权重
checkpoint = torch.load(checkpoint_path, map_location=device)
policy.load_state_dict(checkpoint["model_state_dict"])
policy.eval()

# 推理
actions = policy.act_inference(obs_policy)
```

## 问题2: step()返回值数量变化

### 错误信息

```
File "/home/gwh/dashgo_rl_project/play.py", line 165, in main
    obs_dict, _, _, _ = env.step(zero_actions)
ValueError: too many values to unpack (expected 4)
```

### 问题分析

**根本原因**: Isaac Lab新版本改变了`step()`的返回值签名

**API对比**:
```python
# 旧版（Gym标准）- 4个返回值
obs, reward, done, info = env.step(actions)

# 新版（Gymnasium标准）- 5个返回值
obs, reward, terminated, truncated, info = env.step(actions)
# terminated: 自然终止（到达目标等）
# truncated: 强制终止（超时等）
# done = terminated | truncated
```

### 解决方案

**架构师建议**: 兼容性处理，自动检测返回值数量

**实施代码**:
```python
step_ret = env.step(actions)

# 兼容性处理
if len(step_ret) == 5:
    # 新版API
    obs_dict, rewards, terminated, truncated, extras = step_ret
    dones = terminated | truncated
elif len(step_ret) == 4:
    # 旧版API
    obs_dict, rewards, dones, extras = step_ret
else:
    raise ValueError(f"未知的step返回值数量: {len(step_ret)}")
```

**同样处理reset()**:
```python
reset_ret = env.reset()
if isinstance(reset_ret, tuple):
    obs_dict = reset_ret[0]  # 新版返回 (obs, info)
else:
    obs_dict = reset_ret     # 旧版只返回obs
```

## 问题3: ActorCritic初始化参数错误

### 错误信息

```
TypeError: ActorCritic.__init__() missing 2 required positional arguments: 'obs' and 'obs_groups'
```

### 问题分析

**根本原因**: RSL-RL的`ActorCritic`类需要特定的参数格式

**错误尝试**:
```python
# ❌ 错误：使用num_actor_obs参数
policy = ActorCritic(
    num_actor_obs=num_obs,
    num_critic_obs=num_obs,
    num_actions=num_actions,
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
).to(device)
```

**正确方式**:
```python
# ✅ 正确：使用obs (TensorDict)和obs_groups参数
from tensordict import TensorDict

obs_tensor = TensorDict({
    "policy": torch.randn(num_envs, num_obs, device=device)
}, batch_size=[num_envs])

policy = ActorCritic(
    obs=obs_tensor,                    # 必须是TensorDict
    obs_groups={"policy": ["policy"]}, # 必须提供obs_groups
    num_actions=num_actions,
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
    init_noise_std=1.0,
).to(device)
```

### 解决方案

1. **恢复tensordict依赖**
   - `from tensordict import TensorDict`
   - RSL-RL要求使用TensorDict包装观测数据

2. **从配置文件读取参数**
   - `actor_hidden_dims`, `critic_hidden_dims`, `activation`, `init_noise_std`
   - 确保与训练时完全一致

3. **提供必需的参数**
   - `obs`: TensorDict格式的观测张量
   - `obs_groups`: 观测组配置字典

## 问题4: obs_groups 缺失 critic 键

### 错误信息

```
File "/home/gwh/.conda/envs/env_isaaclab/lib/python3.10/site-packages/rsl_rl/modules/actor_critic.py", line 46, in __init__
    for obs_group in obs_groups["critic"]:
KeyError: 'critic'
```

### 问题分析

**根本原因**: RSL-RL的`ActorCritic`类在初始化时强制要求`obs_groups`字典必须包含`"critic"`键

**发生位置**: `ActorCritic.__init__()` 内部逻辑（rsl_rl/modules/actor_critic.py:46）

**为什么会这样**：
- ActorCritic类包含Actor网络和Critic网络两部分
- 初始化时需要知道两个网络分别使用哪些观测数据
- 即使推理阶段只使用Actor，初始化时也必须满足完整的参数要求

**错误代码**:
```python
# ❌ 错误：只定义了policy组
obs_groups = {"policy": ["policy"]}
policy = ActorCritic(obs=obs_dict, obs_groups=obs_groups, ...)
# 结果：KeyError: 'critic'
```

**正确代码**:
```python
# ✅ 正确：同时定义policy和critic组
obs_groups = {
    "policy": ["policy"],  # Actor网络使用policy观测
    "critic": ["policy"]   # Critic网络也使用policy观测（可以共享）
}
policy = ActorCritic(obs=obs_dict, obs_groups=obs_groups, ...)
# 结果：成功初始化
```

### 解决方案

**实施步骤**:
1. 在构造obs_groups时添加"critic"键
2. 让Critic与Actor共享同一组观测数据（因为环境只输出了policy组）
3. 不影响推理性能（Critic网络在推理时不被调用）

**关键代码**:
```python
# [v5.1 核心修复]
# RSL-RL 强制要求 obs_groups 包含 "critic" 键
# 我们的环境只输出了 "policy" 组，所以让 critic 指向同一组数据
obs_groups = {
    "policy": ["policy"],
    "critic": ["policy"]  # <--- 必须添加这一行
}

policy = ActorCritic(
    obs=obs_dict,              # 必需: 观测样本
    obs_groups=obs_groups,     # 必需: 分组定义 (含 critic)
    num_actions=num_actions,   # 必需: 动作维度
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
    init_noise_std=1.0,
).to(device)
```

### RSL-RL 内部逻辑说明

`ActorCritic.__init__()` 内部会执行：
```python
# rsl_rl/modules/actor_critic.py 第46行
for obs_group in obs_groups["critic"]:  # <--- 这里会报KeyError
    # 初始化Critic网络...
```

这是强校验，无法绕过。必须提供完整的obs_groups定义。

## 问题5: 观测归一化层缺失

### 错误信息

```
RuntimeError: Error(s) in loading state_dict for ActorCritic:
    Unexpected key(s) in state_dict:
    "actor_obs_normalizer._mean",
    "actor_obs_normalizer._var",
    "actor_obs_normalizer._std",
    "actor_obs_normalizer.count",
    "critic_obs_normalizer._mean",
    "critic_obs_normalizer._var",
    "critic_obs_normalizer._std",
    "critic_obs_normalizer.count".
```

### 问题分析

**根本原因**: 训练时开启了观测归一化，但推理脚本构建网络时默认关闭

**发生位置**: `policy.load_state_dict(loaded_dict['model_state_dict'])`

**为什么会这样**：

1. **训练配置**: `train_cfg_v2.yaml` 中设置了 `empirical_normalization: True`
2. **权重文件**: 训练过程中保存了观测数据的统计信息（均值、方差、计数）
3. **推理脚本**: 默认 `actor_obs_normalization=False`，网络结构中没有归一化层
4. **加载冲突**: 权重文件包含归一化参数，但网络结构没有对应层，导致加载失败

**错误代码**:
```python
# ❌ 错误：默认关闭归一化
policy = ActorCritic(
    obs=obs_dict,
    obs_groups=obs_groups,
    num_actions=num_actions,
    # 默认 actor_obs_normalization=False
    # 默认 critic_obs_normalization=False
)
# 结果：权重加载失败 - Unexpected key(s)
```

**正确代码**:
```python
# ✅ 正确：显式开启归一化
policy = ActorCritic(
    obs=obs_dict,
    obs_groups=obs_groups,
    num_actions=num_actions,
    actor_obs_normalization=True,   # <--- 必须开启
    critic_obs_normalization=True,  # <--- 必须开启
)
# 结果：成功加载权重
```

### 解决方案

**实施步骤**:
1. 在 `ActorCritic` 初始化时添加 `actor_obs_normalization=True`
2. 同时添加 `critic_obs_normalization=True`
3. 确保与训练配置一致（`train_cfg_v2.yaml` 中的 `empirical_normalization`）

**关键代码**:
```python
# [v6.0 核心修复] 开启归一化，匹配训练 Checkpoint 结构
policy = ActorCritic(
    obs=obs_dict,
    obs_groups=obs_groups,
    num_actions=num_actions,
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
    init_noise_std=1.0,
    # 必须开启归一化
    actor_obs_normalization=True,
    critic_obs_normalization=True,
).to(device)
```

### 观测归一化的作用

**训练时**:
- 统计观测数据的均值和方差（RunningMeanStd）
- 每次输入前归一化：`(obs - mean) / std`
- 加速训练收敛，提高稳定性

**推理时**:
- 使用训练时保存的统计信息
- 确保输入数据分布与训练时一致
- **如果不开启归一化**，输入数据范围可能不同，导致策略失效

**验证方法**:
```python
# 检查权重文件是否包含归一化参数
checkpoint = torch.load("model_4999.pt")
print(checkpoint["model_state_dict"].keys())
# 应该看到: "actor_obs_normalizer._mean", ...
```

## 关键经验教训

### 1. Isaac Lab API变化频繁
- ⚠️ 版本间API不兼容常见
- ✅ 参考官方文档时必须确认版本号
- ✅ 使用兼容性处理而非硬编码

### 2. RSL-RL Runner的局限性
- `OnPolicyRunner`依赖于特定环境API
- 在Isaac Lab 0.46+中不兼容
- ✅ 直接使用网络类更稳定

### 3. 兼容性处理的重要性
```python
# 好的做法：自动检测
if len(step_ret) == 5:
    # 处理新版
elif len(step_ret) == 4:
    # 处理旧版

# 坏的做法：硬编码
obs, rew, done, info = env.step()  # 只支持旧版
```

### 4. 问题记录的重要性
- 用户提醒："一定要记得记录问题"
- 避免重复踩坑
- 方便后续维护
