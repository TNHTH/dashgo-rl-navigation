## 🔬 根本原因分析

### 问题根源：训练与推理的归一化配置不匹配

**训练时**（`train_v2.py`）:
```python
policy = ActorCritic(
    obs=obs_dict,
    obs_groups=obs_groups,
    num_actions=num_actions,
    actor_hidden_dims=[512, 256, 128],
    critic_hidden_dims=[512, 256, 128],
    activation='elu',
    init_noise_std=1.0,
    # ✅ 开启归一化
    actor_obs_normalization=True,   # 开启
    critic_obs_normalization=True,  # 开启
).to(device)

# 保存时包含归一化层参数
torch.save({
    'model_state_dict': policy.state_dict(),  # 包含 normalizer
    # ...
}, checkpoint_path)
```

**推理时 - no_norm模式**（`debug_play.py`）:
```python
# 根据测试类型决定是否开启归一化
enable_norm = (args_cli.test != "no_norm")

policy = ActorCritic(
    obs=obs_dict,
    obs_groups=obs_groups,
    num_actions=num_actions,
    # ...
    # ❌ 关闭归一化
    actor_obs_normalization=enable_norm,   # False
    critic_obs_normalization=enable_norm,  # False
).to(device)

# 尝试加载包含归一化参数的权重
loaded_dict = torch.load(ckpt_path, map_location=device)
policy.load_state_dict(loaded_dict['model_state_dict'])  # ❌ 报错！
```

### 为什么会冲突？

1. **训练时**: ActorCritic 创建了归一化层（`actor_obs_normalizer`, `critic_obs_normalizer`）
   - 这些层有可学习参数：`_mean`, `_var`, `_std`, `count`
   - 保存到 checkpoint 时包含这些参数

2. **推理时 - no_norm**: ActorCritic **没有创建**归一化层
   - 因为 `actor_obs_normalization=False`
   - 网络结构中不存在 `actor_obs_normalizer` 等属性

3. **加载权重时**: PyTorch 发现 state_dict 中有归一化参数，但网络中没有对应的层
   - 报错：`Unexpected key(s) in state_dict`

## 🛠️ 解决方案

### 实施的修复（已应用）

**修改文件**: `debug_play.py` (第146-159行)

**修复逻辑**:
```python
loaded_dict = torch.load(ckpt_path, map_location=device)
model_state_dict = loaded_dict['model_state_dict']

# [修复] 如果关闭归一化，删除归一化层参数（避免加载错误）
if not enable_norm:
    # 找到所有包含 'normalizer' 的键
    keys_to_remove = [k for k in model_state_dict.keys() if 'normalizer' in k]
    # 删除这些键
    for key in keys_to_remove:
        del model_state_dict[key]
    if keys_to_remove:
        print(f"[INFO] 已删除 {len(keys_to_remove)} 个归一化层参数（因关闭归一化）")

policy.load_state_dict(model_state_dict)
policy.eval()
```

**修复效果**:
- ✅ `--test straight_line`: 正常运行（保留归一化参数）
- ✅ `--test print_obs`: 正常运行（保留归一化参数）
- ✅ `--test no_norm`: **现在可以正常运行**（删除归一化参数）

## 📊 技术细节

### RSL-RL 的归一化层实现

**RunningMeanStd 机制**:
```python
class RunningMeanStd:
    def __init__(self, shape, epsilon=1e-4):
        self._mean = torch.zeros(shape)  # 均值
        self._var = torch.ones(shape)    # 方差
        self._std = torch.ones(shape)    # 标准差
        self.count = 0                   # 样本计数

    def update(self, x):
        # 更新统计量（在线算法）
        batch_mean = x.mean(dim=0)
        batch_var = x.var(dim=0)
        batch_count = x.size(0)

        # 更新全局统计量
        delta = batch_mean - self._mean
        total_count = self.count + batch_count

        new_mean = self._mean + delta * batch_count / total_count
        M_a = self._var * self.count
        M_b = batch_var * batch_count
        M2 = M_a + M_b + delta**2 * self.count * batch_count / total_count
        new_var = M2 / total_count

        self._mean = new_mean
        self._var = new_var
        self._std = torch.sqrt(new_var + epsilon)
        self.count = total_count
```

**归一化过程**:
```python
normalized_obs = (obs - mean) / (std + epsilon)
```

### 为什么训练初期的统计量会"中毒"？

**训练初期**（前100-200 iter）:
```
Episode 1-10: 机器人疯狂发抖刷分
  lin_vel: [-8.0, +7.5, -9.2, +8.8, ...]  ← 极端值
  ang_vel: [-6.5, +7.0, -7.3, +6.9, ...]  ← 极端值

RunningMeanStd 记录：
  mean ≈ 0.0 (正负抵消)
  var  ≈ 50.0 (极端方差！)
  std  ≈ 7.0 (极端标准差！)
```

**训练中期**（200-1000 iter）:
```
策略学会正常导航：
  lin_vel: [0.2, 0.25, 0.18, ...]  ← 正常值
  ang_vel: [0.5, -0.3, 0.4, ...]   ← 正常值

但归一化统计量已经脏了：
  mean ≈ 0.0 (还算正常)
  var  ≈ 20.0 (仍然很高！)
  std  ≈ 4.5 (仍然很高！)
```

**推理时**:
```python
# 正常观测
obs = 0.1  # m/s

# 归一化后
normalized_obs = (0.1 - 0.0) / 4.5 = 0.022  # 被严重缩小！

# 神经网络认为是"异常小"的速度
# 输出极端动作来"纠正"这个"异常"
action_v = 9.0  # m/s (试图加速！)
action_w = -7.5 # rad/s (试图转向！)
```

## 🎯 经验教训

### 1. 训练初期的"刷分"行为污染归一化统计量

**问题**: PPO训练初期，策略为了快速获得奖励，会学会"疯狂发抖"
- 高频正反向切换
- 极端速度值
- 导致归一化统计量异常

**解决方案**:
- 在训练脚本中添加**动作裁剪**（已在 `dashgo_env_v2.py` 中实现）
- 考虑在训练初期（前100 iter）禁用归一化统计量更新
- 或者设置 `init_noise_std=1.0` 增加探索，避免快速收敛到局部最优

### 2. 推理时需要灵活处理归一化层

**问题**: 不同测试模式需要不同的归一化配置
- `straight_line` / `print_obs`: 需要归一化（与训练一致）
- `no_norm`: 不需要归一化（测试归一化是否中毒）

**解决方案**:
- 加载权重前检查归一化配置
- 如果配置不匹配，删除对应的参数
- 避免加载错误

### 3. 调试工具的鲁棒性设计

**问题**: 调试脚本需要支持多种测试模式，但每种模式的要求不同

**设计原则**:
```python
# 1. 根据测试模式动态配置
enable_norm = (args_cli.test != "no_norm")

# 2. 加载时处理不匹配
if not enable_norm:
    # 删除归一化参数
    keys_to_remove = [k for k in model_state_dict.keys() if 'normalizer' in k]
    for key in keys_to_remove:
        del model_state_dict[key]

# 3. 打印配置信息
print(f"[INFO] 归一化状态: {'开启' if enable_norm else '关闭'}")
if keys_to_remove:
    print(f"[INFO] 已删除 {len(keys_to_remove)} 个归一化层参数")
```
