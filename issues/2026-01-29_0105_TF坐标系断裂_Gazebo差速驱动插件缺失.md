# TF坐标系断裂问题 - Gazebo差速驱动插件缺失

> **创建时间**: 2026-01-29 01:05:00
> **严重程度**: 🔴 致命（无法定位和控制）
> **状态**: ✅ 已修复
> **相关文件**: dashgo_d1_sim.urdf.xacro
> **对话来源**: dialogue-001-gazebo-rviz-diagnosis.md

---

## 问题描述

### 现象：RViz TF报错

**错误信息**:
```
RobotModel Error:
- base_link: "No transform from [base_link] to [odom]"
- laser_link: "No transform from [laser_link] to [odom]"
- left_wheel_link: "No transform from [left_wheel_link] to [odom]"
- right_wheel_link: "No transform from [right_wheel_link] to [odom]"
```

**影响**:
- ❌ 机器人无法定位（没有odom→base_link变换）
- ❌ 机器人无法控制（TF树断裂）
- ❌ 导航完全失效

---

## 根本原因

**诊断**: URDF中缺少Gazebo差速驱动插件

**后果**:
- 没有节点发布odom→base_link的TF变换
- robot_state_publisher无法工作
- TF坐标系树断裂

---

## 解决方案

### 添加Gazebo差速驱动插件

**文件**: `dashgo_d1_sim.urdf.xacro`
**位置**: 第150-171行

**代码**:
```xml
<gazebo>
  <plugin name="differential_drive_controller" filename="libgazebo_ros_diff_drive.so">
    <updateRate>50</updateRate>
    <leftJoint>left_wheel_joint</leftJoint>
    <rightJoint>right_wheel_joint</rightJoint>
    <wheelSeparation>0.342</wheelSeparation>
    <wheelDiameter>0.1264</wheelDiameter>
    <wheelAcceleration>1.0</wheelAcceleration>
    <wheelTorque>20</wheelTorque>
    <commandTopic>cmd_vel</commandTopic>
    <odometryTopic>odom</odometryTopic>
    <odometryFrame>odom</odometryFrame>
    <robotBaseFrame>base_link</robotBaseFrame>
    <odometrySource>world</odometrySource>
    <publishWheelTF>true</publishWheelTF>
    <publishOdomTF>true</publishOdomTF>
    <publishWheelJointState>true</publishWheelJointState>
    <covariance_x>0.0001</covariance_x>
    <covariance_y>0.0001</covariance_y>
    <covariance_yaw>0.01</covariance_yaw>
  </plugin>
</gazebo>
```

**关键参数**:
- `publishOdomTF`: 必须为true（发布odom→base_link TF）
- `wheelSeparation`: 0.342m（与实物参数对齐）
- `wheelDiameter`: 0.1264m（与实物参数对齐）

**功能**:
- ✅ 发布odom→base_link TF变换
- ✅ 订阅/cmd_vel控制命令
- ✅ 发布/odom里程计数据

## 验证方法

### 1. 检查TF树

```bash
rosrun tf view_frames
# 应生成frames.pdf，显示完整的TF树
```

**预期结构**:
```
odom (里程计坐标系)
  └─ base_link (机器人基座)
      ├─ left_wheel_link (左轮)
      ├─ right_wheel_link (右轮)
      └─ laser_link (雷达)
```

### 2. 检查TF变换

```bash
# 不应该报错
rosrun tf tf_echo odom base_link
# 应该输出变换矩阵
```

### 3. 动态验证

```bash
# 发送旋转指令
rostopic pub -1 /cmd_vel geometry_msgs/Twist '{linear: {x: 0.0}, angular: {z: 0.5}}'

# 观察RViz中TF箭头是否旋转
# 只要TF箭头在转 = 控制链路打通
```

## 经验教训

### 1. URDF必须包含Gazebo插件

**教训**: 仅定义几何体是不够的

必须添加仿真插件才能：
- 发布TF变换
- 订阅控制命令
- 发布传感器数据

### 2. 差速驱动插件是核心

**教训**: libgazebo_ros_diff_drive.so是移动机器人的"神经系统"

没有它：
- 没有TF = 无法定位
- 不订阅cmd_vel = 无法控制
