## 📋 方案概述

**方案目标**：禁用RL节点，启用MoveBase控制，验证传统导航是否正常工作

**预期结果**：
- ✅ 如果传统导航正常 → **确诊RL模型问题** → 执行方案C（添加转动惩罚，重新训练）
- ❌ 如果传统导航仍然转圈 → **物理层问题**（摩擦力/动力学/万向轮参数）

## 🔍 本地环境分析

### 当前系统架构

**sim2real_golden.launch** 当前启动的组件：
1. ✅ Gazebo仿真（empty_world）
2. ✅ 机器人状态发布（robot_state_publisher）
3. ✅ SLAM建图（Gmapping）
4. ✅ Rviz可视化
5. ✅ **RL导航节点**（geo_nav_node.py）← **需要禁用**
6. ❌ **没有启动move_base** ← **需要添加**

### 发现的关键问题

**问题1：缺少move_base启动配置**
- `sim2real_golden.launch` 没有启动 `move_base` 节点
- 需要手动添加 move_base 的 include 语句

**问题2：cmd_vel topic冲突**
- RL节点（geo_nav_node.py）发布到 `/cmd_vel`
- move_base也会发布到 `/cmd_vel`
- 两个节点同时控制会导致冲突

**问题3：使用TEB而非DWA**
- `/dashgo/1/1/nav/param/base_local_planner_teb_params.yaml` 使用 TEB（Timed Elastic Band）
- 架构师建议使用 DWA（Dynamic Window Approach）
- TEB的参数配置与DWA不同

## 📊 关键差异：DWA vs TEB

### 架构师推荐：DWA（Dynamic Window Approach）

**优点**：
- ✅ 简单、高效、稳定
- ✅ 参数调节直观
- ✅ 对动态环境响应快
- ✅ ROS官方推荐

**配置文件**：`base_local_planner_dwa_params.yaml`

**关键参数**：
```yaml
DWAPlannerROS:
  max_vel_x: 0.3              # 最大线速度
  max_vel_theta: 1.0          # 最大角速度
  acc_lim_x: 1.5              # 线加速度限制
  acc_lim_theta: 1.0          # 角加速度限制
  sim_time: 1.7               # 前向模拟时间
  path_distance_bias: 32.0    # 路径距离权重
  goal_distance_bias: 24.0    # 目标距离权重
  occdist_scale: 0.01         # 障碍物距离权重
```

### 当前DashGo配置：TEB（Timed Elastic Band）

**优点**：
- ✅ 轨迹优化更精细
- ✅ 支持动态窗口调整
- ✅ 适合复杂环境

**缺点**：
- ⚠️ 参数调节复杂
- ⚠️ 对时间同步敏感
- ⚠️ 可能与Gmapping配合不佳

**配置文件**：`base_local_planner_teb_params.yaml`

**关键参数**（已从文件中读取）：
```yaml
TebLocalPlannerROS:
  max_vel_x: 0.3
  max_vel_theta: 1.0
  acc_lim_x: 1.5
  acc_lim_theta: 1.0
  xy_goal_tolerance: 0.2
  yaw_goal_tolerance: 0.2
  min_obstacle_dist: 0.1
```

### 建议策略

**方案A-1（保守）**：先使用DWA验证
- 理由：DWA更稳定，验证结果更可靠
- 如果DWA正常 → 确诊RL问题
- 如果DWA失败 → 再试TEB

**方案A-2（激进）**：直接使用TEB
- 理由：保持DashGo原有配置
- 但TEB可能与Gmapping配合不佳

**推荐**：方案A-1（使用DWA）
