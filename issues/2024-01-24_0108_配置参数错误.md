## 问题描述

运行play.py时出现FATAL错误：

```
[FATAL] 未捕获的异常: PPO.__init__() got an unexpected keyword argument 'learning_rate_schedule'
```

**错误现象**:
- 程序启动时立即崩溃
- 无法加载训练配置
- 阻塞所有训练任务

---

## 根本原因

### 1. 直接原因
在 `train_cfg_v2.yaml` 中添加了RSL-RL的PPO不支持的参数：
```yaml
learning_rate: 3.0e-4
learning_rate_schedule: linear  # ❌ PPO不支持
lr_decay_fraction: 0.5         # ❌ PPO不支持
```

### 2. 深层原因
- **未验证API就添加参数**: 基于假设添加了参数，没有先用`inspect.signature()`验证
- **违反项目规则**: 违反了"官方文档优先"原则，没有查阅RSL-RL官方文档
- **缺少测试**: 修改配置后没有运行验证脚本测试

### 3. 为什么会犯这个错误
- 假设学习率调度是"常见功能"，所有PPO实现都应该支持
- 没有意识到不同RL库的实现差异
- 看到其他项目有类似配置，就直接复制过来

---

## 解决方案

### 方案A: 移除不支持的参数（已采用）

**修改前**（train_cfg_v2.yaml:28-41）:
```yaml
algorithm:
  class_name: PPO
  value_loss_coef: 1.0
  use_clipped_value_loss: True
  clip_param: 0.2
  num_learning_epochs: 5

  # [优化] 学习率调度：保持初始值3e-4，训练时线性衰减
  learning_rate: 3.0e-4
  learning_rate_schedule: linear  # ❌ 不支持
  lr_decay_fraction: 0.5  # ❌ 不支持

  max_grad_norm: 1.0
  gamma: 0.99
  lam: 0.95
  desired_kl: 0.01
```

**修改后**:
```yaml
algorithm:
  class_name: PPO
  value_loss_coef: 1.0
  use_clipped_value_loss: True
  clip_param: 0.2
  num_learning_epochs: 5

  # [优化] 使用保守的学习率提高稳定性
  learning_rate: 1.0e-4  # 降低到保守值

  max_grad_norm: 1.0
  gamma: 0.99
  lam: 0.95
  desired_kl: 0.01
```

**变更说明**:
- 移除 `learning_rate_schedule: linear`
- 移除 `lr_decay_fraction: 0.5`
- 学习率从 `3e-4` 降到 `1e-4`（更保守，更稳定）

## 经验教训

### 1. 永远不要假设API支持某参数
- ❌ 错误做法: "应该支持学习率调度吧，加上试试"
- ✅ 正确做法: 先用`inspect.signature()`验证支持的参数

### 2. 遵守"官方文档优先"原则
- ❌ 错误做法: 看到其他项目有这个配置，我也加
- ✅ 正确做法: 查阅官方文档确认参数支持

### 3. 修改配置后必须验证
- ❌ 错误做法: 修改配置直接运行
- ✅ 正确做法: 运行验证脚本测试配置有效性

### 4. 保守的学习率策略
- ❌ 错误做法: 使用推荐值的上界（3e-4）
- ✅ 正确做法: 从保守值开始（1e-4），逐步调试
