## 🎯 问题现象

### 用户描述

训练完成的 DashGo 机器人导航策略出现严重的"醉汉走路"现象：
- 机器人一直带着一定角速度转圈，不走直线
- 感觉不知道目标在哪，一直在乱逛
- 训练虽然收敛（达到5000 iterations），但部署效果完全不符合预期

### 测试数据对比

| 测试模型 | 训练进度 | 动作范围（网络输出） | 机器人行为 |
|---------|---------|---------------------|-----------|
| model_1900.pt | 38% (1900 iter) | v=±9.0, w=±7.5 | 持续后退，远离目标 |
| model_4999.pt | 100% (4999 iter) | v=±10, w=±13 | **持续后退，远离目标** ❌ |
| **正常预期** | - | v=±0.3, w=±1.0 | 朝目标移动，到达后停止 |

**关键发现**：
- ✅ 物理参数正常（强制走直线测试通过）
- ✅ 坐标系计算正常（目标角度符号正确）
- ❌ **训练模型已损坏**（最新模型也有同样问题）
- ❌ 机器人学会了"远离目标"的策略（与预期相反）

## 🔍 根本原因分析

### 原因1：奖励函数设计问题 ⭐

#### 问题代码：`reward_target_speed` 函数定义冲突

**发现位置**: `dashgo_env_v2.py` (第1973-1998行)

```python
# 定义1（旧版本）- 只鼓励前进
def reward_target_speed(env, asset_cfg):
    """
    [v5.0] 速度对齐奖励：鼓励使用接近最优速度的速度
    优化版本：直接鼓励向前移动，更简单直接
    """
    vel = env.scene[asset_cfg.name].data.root_lin_vel_b[:, 0]
    return torch.clamp(vel, min=0.0)  # ✅ 只奖励正速度（前进）

# 定义2（新版本）- 匹配目标速度（不管方向！）
def reward_target_speed(env: ManagerBasedRLEnv, asset_cfg: SceneEntityCfg) -> torch.Tensor:
    """
    速度匹配奖励（后来添加的版本？）
    """
    robot = env.scene[asset_cfg.name]
    lin_vel_b = torch.nan_to_num(robot.data.root_lin_vel_b[:, 0], nan=0.0, posinf=0.0, neginf=0.0)
    target_vel = 0.25
    speed_match = 1.0 - torch.abs(lin_vel_b - target_vel) / target_vel
    return torch.clamp(speed_match, 0.0, 0.2)  # ❌ 奖励任何方向的速度！
```

**问题分析**：
- 第二个定义鼓励机器人以 **0.25 m/s** 的速度移动
- **但不管朝向**！如果机器人朝后移动，也会得到奖励
- 这导致机器人学会了"快速后退刷分"的策略

#### 奖励配置

**发现位置**: `dashgo_env_v2.py` (第983-987行)

```python
target_speed = RewardTermCfg(

```

#### 当前奖励权重分布

```python
+----------------------------------------+
|          Active Reward Terms           |
+-------+-----------------------+--------+
| Index | Name                  | Weight |
+-------+-----------------------+--------+
|   0   | reach_goal            | 2000.0 |  # 稀疏奖励
|   1   | shaping_distance      |   0.75 |  # Dense引导
|   2   | target_speed          |    1.0 |  # ⚠️ 问题项
|   3   | facing_goal           |    0.1 |  # 辅助
|   4   | velodyne_style_reward |    1.0 |  # Dense
+-------+-----------------------+--------+
```

**冲突分析**：
- `target_speed` (weight=1.0) 鼓励快速移动（不管方向）
- `shaping_distance` (weight=0.75) 鼓励靠近目标
- 当两者冲突时，`target_speed` 可能获胜（更容易刷分）
- 结果：机器人学会"快速后退"而不是"靠近目标"

### 原因2：观测归一化层可能中毒

#### 问题机制

**训练初期**（前100-200 iterations）：
```python
# 机器人策略：疯狂发抖刷分
Episode 1-10: 机器人动作
  lin_vel: [-8.0, +7.5, -9.2, +8.8, ...]  ← 极端值
  ang_vel: [-6.5, +7.0, -7.3, +6.9, ...]  ← 极端值

# RunningMeanStd 记录了这些极端统计量：
mean ≈ 0.0 (正负抵消)
var  ≈ 50.0 (极端方差！)
std  ≈ 7.0 (极端标准差！)
```

**训练中期**（200-1000 iterations）：
```python

  lin_vel: [0.2, 0.25, 0.18, ...]  ← 正常值
  ang_vel: [0.5, -0.3, 0.4, ...]   ← 正常值

# 但归一化统计量已经"脏"了：
  var  ≈ 20.0 (仍然很高！)
  std  ≈ 4.5 (仍然很高！)
```

**推理时**（当前）：
```python
# 正常观测
```

### 代码2：距离奖励函数（正常）

**文件**: `dashgo_env_v2.py` (第1950-1972行)

```python
def reward_position_command_error_tanh(env, std: float, command_name: str, asset_cfg: SceneEntityCfg) -> torch.Tensor:
    """
    [v5.0 Hotfix] 手动实现tanh距离奖励

    奖励范围: (0, 1]
    逻辑: 距离越近，奖励越高（接近1）；距离越远，奖励越低（接近0）

    数学原理:
        reward = 1.0 - tanh(dist / std)
        - 当 dist = 0, tanh = 0, reward = 1.0（到达目标）
        - 当 dist = std, tanh ≈ 0.76, reward ≈ 0.24（中等距离）
        - 当 dist >> std, tanh ≈ 1.0, reward ≈ 0.0（远距离）
    """
    # 1. 获取目标位置 (x, y)
    target_pos = env.command_manager.get_command(command_name)[:, :2]

    # 2. 获取机器人位置 (x, y)
    robot_pos = env.scene[asset_cfg.name].data.root_pos_w[:, :2]

    # 3. 计算欧几里得距离
    dist = torch.norm(target_pos - robot_pos, dim=1)

    # 4. 计算tanh奖励
    return 1.0 - torch.tanh(dist / std)
```
